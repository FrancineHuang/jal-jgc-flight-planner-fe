# JGC Flight Planner

[English](README.md) | **日本語** | [简体中文](README.zh-CN.md)

JALのJGCを目指す「修行僧」のためのフライトプランニングツール。

現在のポイント、目標までの進捗、予定の旅程、1ポイントあたりの費用をひとつの画面にまとめ、次のフライトを計画しやすくします。

このリポジトリは、Next.jsで構築したプロジェクトの**フロントエンドアプリケーション**です。画面の初期表示は日本語で、英語と簡体字中国語にも対応しています。

## プロジェクトの背景

このプロジェクトは、JALグローバルクラブ（JGC）を目指し、路線やポイント獲得効率を考えることが好きな方に向けて開発しています。ここでいう「修行」とは、常旅客としての目標に合わせてフライトを計画することです。行き先だけでなく、その旅で目標にどのくらい近づけるか、どれだけの予算が必要かも計画の対象になります。

JALの[Life Status プログラム](https://www.jal.co.jp/jp/ja/jmb/lsp/)は、フライトや対象のライフスタイルサービスの利用に応じてLife Status ポイント（LSP）がたまる生涯実績プログラムです。本プロジェクトは、その中でも**フライトの計画**に焦点を当て、次のような疑問に答えることを目指しています。

- 現在のLSPはいくつで、自分の目標まであとどのくらいか。
- 予定している片道・往復の旅程で、どのくらいのLSPが見込めるか。
- この航空券の1 LSPあたりの費用はどのくらいで、予算に合っているか。
- どのバージョンのポリシーで試算され、どの区間の対象可否が未確認なのか。

手動入力と計算根拠を追える試算から始め、「JGC修行」の計画に役立つ体験を少しずつ整えていきます。また、AIの支援を活用して開発するフルスタックのエンジニアリング・ポートフォリオでもあります。

> 現在はプロトタイプです。すべてのフライトのポイント計算は**未検証のデモ試算**であり、JALの公式な獲得ポイントを保証するものではありません。公式情報へのリンクは、実装した計算ルールの検証完了を意味しません。LSPと年間のFLY ON ポイントは異なる概念です。本プロジェクトは独立して開発しており、日本航空とは関係ありません。

公式の参考情報：[JAL Life Status プログラム](https://www.jal.co.jp/jp/ja/jmb/lsp/)・[Star グレードの説明](https://www.jal.co.jp/jp/ja/jmb/lsp/jgc/)。実際のポイント、対象条件、特典については、JALが公表する最新の条件をご確認ください。

## 現在の機能

| 機能 | 内容 |
| --- | --- |
| LSPダッシュボード | 現在のLSPと個人の目標を手動で設定し、残りのポイントと達成率を表示 |
| フライトシミュレーター | 片道・往復の空港、日付、航空券の合計金額、販売航空会社を入力 |
| 区間ごとの対象可否 | 対象・対象外・未確認を手動で指定し、空港だけでは対象可否を判断しない |
| ポイントと費用のプレビュー | バックエンドが返す獲得見込みLSP、円／LSP、区間ごとの内訳を表示 |
| ポリシーの可視化 | ポリシーID、バージョン、検証状況、デモに関する注意事項を表示 |
| 多言語対応 | 日本語・英語・簡体字中国語に対応し、サイドバーからの言語選択を保存 |
| レスポンシブ画面 | デスクトップとスマートフォンに対応し、読み込み中・未入力・入力エラー・再試行の状態を表示 |

現在のポイントと目標には編集可能なデモ値を使い、ページの再読み込みでリセットされます。表示言語の設定は現在のブラウザーに保存されます。言語を切り替えても、入力済みの旅程や試算結果は保持されます。

現時点では、JALアカウントとの連携、データベース、実際の航空券価格の取得、対象可否の自動検証には対応していません。旅程履歴の保存や最適な路線の自動検索も未実装です。

### デモ旅程

「羽田〜那覇のデモを試す」をクリックし、続けて「デモLSPを試算する」をクリックすると、次の例をリクエストできます。

| 項目 | デモ値 |
| --- | --- |
| 旅程 | HND → OKA → HND（羽田〜那覇往復） |
| 日付 | 2026年11月1日〜11月3日 |
| 販売航空会社 | JL |
| 航空券の合計金額 | ¥35,000 |
| 対象可否 | 両区間を手動で「対象」に指定 |
| 獲得見込み | 10 デモLSP |
| 1ポイントあたりの費用 | ¥3,500／LSP |

この結果はバックエンドの現在の**未検証デモポリシー**によるもので、公式の計算例ではありません。初期残高、個人の目標、サンプル旅程は[`src/config/demo.ts`](src/config/demo.ts)で設定しています。画面の目標値は、確認済みのJGC入会資格の判定を示すものではありません。

対象可否が未確認、または路線がポリシーの対象範囲外の場合、合計は確認待ちとなり、試算できた区間の結果は保持されます。ポイントが0の場合、1ポイントあたりの費用は算出不可と表示します。

## 技術スタック

| 分野 | 技術 |
| --- | --- |
| フロントエンドフレームワーク | Next.js 16・App Router |
| UI | React 19・TypeScript |
| スタイル | Tailwind CSS 4・CSS・ネイビー、白、落ち着いた暗赤色のアクセント |
| 多言語化 | React Context・JSON言語ファイル・ブラウザーへの言語設定の保存 |
| API通信 | Fetch API・レスポンス形式の検証・タイムアウトとキャンセル処理 |
| コード検査 | ESLint 9・TypeScript |
| フロントエンドテスト | Node.js標準テストランナー・TypeScriptコンパイラー |
| 独立したバックエンド | Express 5・TypeScript・Zod |

フロントエンドとバックエンドは別々のリポジトリで管理しています。

- フロントエンド：[jal-jgc-flight-planner-fe](https://github.com/FrancineHuang/jal-jgc-flight-planner-fe)
- バックエンド：[jal-jgc-flight-planner-be](https://github.com/FrancineHuang/jal-jgc-flight-planner-be)

フロントエンドは入力、検証、画面操作、結果表示を担当し、`POST /api/v1/lsp/estimates`を呼び出します。フライトのLSP計算ロジックはすべてバックエンドが担当し、フロントエンドには計算式を実装していません。

## ローカル環境のセットアップ

### 1. ツールとソースコードの準備

以下は**Node.js 24、npm、Git**を使用する手順です。各コマンドが利用できることを確認してください。

```sh
node --version
npm --version
git --version
```

初めてセットアップする場合は、同じ作業ディレクトリに両方のリポジトリをクローンします。

```sh
mkdir jal-jgc-flight-planner
cd jal-jgc-flight-planner

git clone https://github.com/FrancineHuang/jal-jgc-flight-planner-fe.git
git clone https://github.com/FrancineHuang/jal-jgc-flight-planner-be.git
```

すでにソースコードがある場合は、既存のディレクトリを使い、クローンの手順を省略できます。以下の2つのターミナルは、どちらもこの作業ディレクトリを起点とします。

### 2. バックエンドの起動

1つ目のターミナルで実行します。

```sh
cd jal-jgc-flight-planner-be
npm ci
npm run dev
```

バックエンドの初期アドレスは`http://localhost:4000`で、`http://localhost:3000`からのフロントエンドのリクエストを許可します。この構成で使う場合、バックエンドの環境変数を追加する必要はありません。

別のターミナルから動作を確認できます。

```sh
curl http://localhost:4000/api/health
```

想定されるレスポンス：

```json
{ "status": "ok", "service": "JGC Flight Planner API" }
```

### 3. フロントエンドの設定と起動

2つ目のターミナルで実行します。`cp`は初回の設定ファイル作成用です。すでに`.env.local`がある場合は、このコマンドを省略して既存の設定を保持してください。

```sh
cd jal-jgc-flight-planner-fe
npm ci
cp .env.example .env.local
```

`.env.local`のAPIアドレスを確認します。初期設定は次のとおりです。

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://localhost:4000
```

フロントエンドを起動します。

```sh
npm run dev
```

[http://localhost:3000](http://localhost:3000)を開くと、日本語のダッシュボードが表示されます。サイドバーの「表示言語」メニューから、Englishまたは简体中文に切り替えられます。

フロントエンドだけでも画面は表示できます。フライトの試算を実行するには、バックエンドも起動しておく必要があります。

### 環境変数

| アプリケーション | 変数 | 初期値・例 | 用途 |
| --- | --- | --- | --- |
| フロントエンド | `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:4000` | バックエンドのベースURL。`/api/v1`は含めない |
| バックエンド | `PORT` | `4000` | バックエンドの待ち受けポート |
| バックエンド | `FRONTEND_ORIGIN` | `http://localhost:3000` | CORSで許可するフロントエンドのオリジン |

`NEXT_PUBLIC_API_BASE_URL`はブラウザー向けのコードに含まれるため、秘密情報を設定しないでください。変更した場合は、フロントエンドの開発サーバーを再起動します。本番環境では再ビルドが必要です。共有する設定例には`.env.example`を使い、`.env`と`.env.local`はGitの管理対象から除外しています。

フロントエンドを別のポートで動かす場合、バックエンドの`FRONTEND_ORIGIN`を実際のアクセス先に合わせてください。たとえば、フロントエンドが`http://localhost:3001`の場合、次の設定でバックエンドを再起動します。

```sh
FRONTEND_ORIGIN=http://localhost:3001 npm run dev
```

このコマンドはバックエンドのディレクトリで実行し、macOS、Linux、Git Bashで利用できます。`localhost`と`127.0.0.1`も異なるオリジンとして扱われるため、アドレスを統一してください。

フォントは`next/font/google`経由でGeistを読み込んでいます。初回ビルド時はGoogle Fontsへの接続が必要です。

## 開発時のチェックとビルド

フロントエンドのディレクトリで実行します。

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

フロントエンドのテストは、リクエスト形式、入力値の境界、未確認値とゼロ値、APIエラー、翻訳キーの整合性、日付形式、言語設定の保存を確認します。

バックエンドの起動中は、実際のAPIを使った結合確認も実行できます。

```sh
npm run test:integration
```

結合確認スクリプトの初期接続先は`http://localhost:4000`です。別の接続先を使う場合は、プロセスの環境変数で指定します。

```sh
NEXT_PUBLIC_API_BASE_URL=http://localhost:4001 npm run test:integration
```

本番ビルドが成功した後、次のコマンドでフロントエンドを起動します。

```sh
npm start
```

バックエンドは別途起動し、本番フロントエンドのオリジンからのアクセスを許可しておく必要があります。
